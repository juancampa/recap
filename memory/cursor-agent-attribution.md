**Cursor is modeled to mirror Claude Code**: a composer (agent session) produces both **prompts** and **edits**, all sharing one colored session bar (keyed by `session_id = composerId`). Two data sources feed this — prompts from the composer transcript, edits from Local History (attributed back to a composer). `src/cursor_sessions.rs` does both in one DB pass.

**Prompts** come from type-1 (user) message bubbles (`bubbleId:<composer>:<bubble>` in `cursorDiskKV`). Each becomes a `HistoryEntryKind::Prompt` with `session_id = composerId`, synthetic `file_path = cursor:<composer>:<bubble>` (unique key, like Claude's `claude:<session>:<uuid>`), and `source = EditSource::Cursor`. **Timestamp**: the bubble's own top-level `createdAt` (RFC3339) — present on ~99% (4208/4241); older 2025 composers lack it and are skipped. Bubbles carry NO other per-message time (no `checkpointId`-encoded time, tool `createdAt` is only on assistant edit bubbles), and `composerData.fullConversationHeadersOnly` headers have none either — so `createdAt` is the only prompt timestamp. **Project chain**: composer `trackedGitRepos[].repoPath` (only ~470/1136 composers have it, often `[]`), else backfilled from `find_project_chain` of the composer's own edited-file set (deterministic `min()` pick) — ~67% (2792/4189) end up with a chain; the rest are pure-Q&A or deleted-path composers (shown chain-less, same as a cwd-less Claude prompt). `read_bubbles` (was `read_edit_bubbles`) returns `(files, prompts)`; the SQL prefilter gained `OR value LIKE '%"type":1,%'`. Prompts are emitted into the store in the `LoadEvent::CursorSessions` handler in app.rs (NOT the Cursor Local-History loader thread), deduped by their synthetic key against existing store+accumulated prompts so an mtime-triggered rebuild doesn't double-add.

**LOCAL HISTORY NO LONGER SEES AGENT EDITS (measured 2026-09-05).** Cursor writes a Local History snapshot only for a save that goes through the editor window. The modern `edit_file_v2` tool writes the file directly, so it creates no snapshot. Measurement over all agent edits after 2026-08-01: 1117 edit bursts, 35 with a snapshot = **3%**. The other 97% are invisible to recap. A file can also look "covered" and still miss the agent edits, because the user's own manual saves of that file do produce snapshots.

**IMPLEMENTED 2026-09-05: `cursor_sessions.rs` now reads agent edits from the DB.** `read_bubbles` returns a third value, `Vec<EditRecord>`, one per edit tool call that carries content ids. `build_edits` copies each blob to `~/.cache/recap/cursor/<sha256>` (the blob key IS the sha256 of the content, so the file name deduplicates shared content and a cached blob needs no DB read) and builds a `HistoryEntry` with `session_id = composerId` and the new `HistoryEntry::base_path = Some(before_blob)`. `HistoryStore::prev_snapshot` returns `base_path` when set, so the diff is the exact tool call, not the difference from the previous snapshot. Since 2026-09-11 Claude Code edits carry a `base_path` too (see [[blame]]). `apply_cursor_attribution` skips an entry that has a `base_path`, and it also skips a **prompt** (fixed 2026-09-09): a prompt's synthetic `cursor:<composer>:<bubble>` path matches no file in the composer file sets, so the fuzzy join returned `None` and erased the composer that `prompt_entry` set. The symptom: every Cursor prompt row showed `Session — ` and no `⟨name⟩` label. Test: `cursor_attribution_keeps_the_composer_of_a_prompt` in app.rs. Result on the real store: **19920 agent edits, 642 MB of cache, 18990 files**.

**`toolFormerData.result` and `params` are DOUBLE-encoded**: a JSON string that holds a JSON string that holds the object. `decode_json` unwraps up to 3 string layers. A single `serde_json::from_str` returns `Value::String` and every field lookup then fails silently.

**`cursorDiskKV.value` is TEXT, not BLOB.** `row.get::<_, Vec<u8>>` fails with "Invalid column type Text"; read `String` first and fall back to `Vec<u8>`.

**The replacement source is in the DB.** Each `edit_file_v2` bubble holds `toolFormerData.result` = `{"beforeContentId":"composer.content.<sha256>","afterContentId":"composer.content.<sha256>"}`. Both ids are keys in `cursorDiskKV` and hold the **full plain-text file content** (not a diff, not encrypted). Coverage: 19097 blobs, 604 MB, and every id that a bubble names still resolves. Per month, blobs exist for >95% of agent edits from 2026-01 forward; before 2026-01 the `result` has no content ids. This source also gives exact attribution (path, `createdAt`, composerId), so the fuzzy window join is not necessary for these edits. Local History stays necessary for the user's manual saves and for edits before 2026-01.

**Edits are (still) sourced from Local History in the code** (not the composer transcript): the modern bulk `search_replace` tool records only a `diff`, no after-content, so it can't feed recap's snapshot-diff cleanly, whereas Local History has full content + real save times for every tool. So edits come from one source (no dedup needed) and this module only *attributes* them.

Cursor file edits in recap come from VS Code **Local History** (`~/Library/Application Support/Cursor/User/History/<hash>/entries.json` + snapshots), which logs every file save with **no author**. The agent conversation ("composer", one chat/agent session) lives separately in `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb`, keyed by `composerId` (UUID). `src/cursor_sessions.rs` joins them.

Attribution is a **fuzzy** join (unlike Claude Code's exact `<session>.jsonl` id) — there is no stored resulting-file content to hash-match. Two layers:
1. **`patch-graph:<ws>:meta:<hash>`** (cursorDiskKV) → `patches[].attribs = {fileUri.path, timestamp, patchSource, composerMetadata.composerId}`. Exact per-edit `(path, ms, composerId)`, only for `patchSource=="agent"`. **New Cursor feature, no historical backfill** — covers only recent edits.
2. **composer window + file-set**: each composer has `[createdAt, lastUpdatedAt]` (from `composerHeaders` table cols, or older `composerData:<id>` blobs) and a set of edited files gathered from message bubbles `bubbleId:<composerId>:<bubbleId>`. A snapshot whose path ∈ set and time ∈ window±grace attributes to it; narrowest window wins ties. This is the fuzzy fallback and covers most real history.

**CRITICAL — a Cursor agent edit is recorded THREE different ways** in a bubble depending on client version; miss any and real agent edits attribute to nothing (looks like the feature is broken):
- **modern (current Cursor): a `toolFormerData` TOOL CALL** — `name` is `edit_file`, `edit_file_v2`, or `search_replace`; the path is `params.relativeWorkspacePath` (despite the name, usually ABSOLUTE, occasionally relative). `params` is sometimes a JSON object, sometimes a JSON-encoded STRING (double-parse). This is how nearly all recent edits appear — the legacy fields below are absent.
- agentic: `diffsSinceLastApply[].relativeWorkspacePath` (relative to `trackedGitRepos[].repoPath`).
- legacy/ask: absolute `codeBlocks[].uri.path`.

The SQL prefilter that avoids a full JSON scan MUST match all three: `value LIKE '%"codeBlocks":[{%' OR value LIKE '%"diffsSinceLastApply":[{%' OR value LIKE '%search_replace%' OR value LIKE '%edit_file%'` (~20k rows). `patch-graph` had NOTHING for a July-2026 agent-written file; the tool-call file-set + window is what actually attributed it.

Display name: `composerHeaders.value.name` → falls back to `subtitle` ("Edited x.rs, y.rs").

**Critical perf fact**: `state.vscdb` is **multi-GB** (5.3GB observed). The bubble file-set scan (`value LIKE '%"codeBlocks":[{%'`) reads gigabytes → ~12s even warm; full build ~35s. So `CursorSessions::load()` MUST NOT block the UI or the Cursor edit stream. Design in `src/app.rs`:
- `load_cursor` streams edits with `session_id: None` (fast, unchanged).
- A **separate** background thread builds the map (`load_cached`, counted in `loading_sources` so the channel stays open), sends `LoadEvent::CursorSessions{sessions, mtime}`.
- `apply_cursor_attribution()` post-pass tags Cursor entries by `entry.timestamp.timestamp_millis()`.
- Cached by DB mtime in `Sources.cursor_sessions{,_mtime}` — reloads skip the rebuild unless Cursor's store changed.

`session_id` is reused for the composerId (drives the colored session-bar grouping, same as Claude). But `focus_or_resume_session` in main.rs is **gated to `EditSource::ClaudeCode`** — a Cursor composerId must never be fed to `claude --resume`. The composer NAME is shown as a trailing `⟨name⟩` label (in the session color) via `store.cursor_session_names` on: attributed Cursor **edit** rows, Cursor **prompt** rows (`cursor_session_name` no longer early-returns on prompts — a Claude prompt's session_id simply isn't a composerId so the lookup misses), and the diff `separator_line` header. The prompt branch of `group_row_line` reserves `name.chars()+4` cols in its wrap `avail` so the full-width first line can't overflow the label. Unattributed (manual) edits show no label — that's how the user tells agent edits from their own.

Verified on real data: agent-written `gaze/crates/gref_nav/src/lib.rs` edits attribute to composer "GrefNav widget design"; the user's manual saves of the same file correctly show `<none>`. `#[ignore]`d smoke test `smoke_load_and_attribute` in cursor_sessions.rs.
